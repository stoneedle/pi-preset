# 架构

| `web/src/components/SessionTools.svelte`、`internal/server/session_details.go` | 原生 UUID、文件路径和目录的只读详情、复制及手动压缩入口 |
| `web/src/remote-queue.svelte.js`、`web/src/components/QueuedMessages.svelte` | 原生网页队列的内存只读投影、按需图文取回及逐条取消；不拥有执行调度 |
| `web/src/components/SubmissionRecovery.svelte` | 仅在发送异常或切换草稿后显示单行恢复入口，按需展开原文和图片；不投影为会话消息 |
| `internal/rpc/project_options.mjs`、`project_commands.mjs` | 用 Pi 的模型／设置 API 和包资源发现 API 读取项目选项、技能及 Prompt 模板，不创建 AgentSession 或 worker，不执行扩展或安装包 |
| `web/src/components/` | 工具/思考、图片和通知交互 |

每个 PWA 只连接安装地址对应的电脑，不维护跨主机书签或切换。应用安装名称属于当前电脑，不是主机目录或连接配置。

Pi 拥有执行、队列、工具、名称和记录。子任务提供方拥有子任务事实；只有 `SessionState` 对这些公开事实进行协调，标题、Go 和浏览器不另行推断运行状态。

## 阅读、更新与回复

1. Go 返回不含会话内容的 HTML 壳和带内容哈希的 JavaScript/CSS。`main.js` 挂载同源路由和全局观察，抽屉在会话之间保持同一实例，只有正文等会话专属界面按会话身份重新挂载，没有语言加载或翻译层。
2. `/api/session` 返回最近消息窗口，`/api/status` 与 SSE 提供独立的运行快照。普通正文完整返回；工具和思考只带有界摘要，图片只返回定位元数据，不包含原图或缩略图字节。
3. 点击展开工具／思考时请求 `/api/session/block`；会话图片接近可视区时惰性请求 `/api/session/image?thumbnail=1`，只返回最长边 240px 的 JPEG 缩略图，点击后才通过同一图片接口打开原图。思考没有可读正文时不产生空展开项；工具摘要包括 `codemode` 的 `code` 输入。跳过的块保持原生索引不变。工具和思考摘要及完整正文携带相同的原生版本身份：思考／未完成调用使用所属 entry ID，已完成工具使用结果 entry ID；不能只按 pending／done 判断正文是否仍有效。
4. 前台进入或返回会话，通过 `/api/session/acknowledge` 确认当前已知的精确结果，不必等待正文下载。后台消息、通知到达和会话列表浏览不会确认结果。
5. 原生 JSONL 变化经过监听器防抖，通过 SSE 发送刷新提示。浏览器单飞合并请求，使用 `after` 增量更新稳定消息 ID；`before` 加载历史并保留视口锚点。消息窗口模块在发起请求时固定游标、方向、窗口代次和运行观察代次；窗口重置使旧代次的全部响应失效，运行叶节点变化或连接失效则阻止旧观察下的窗口替换、历史追加及错误。尚未重置窗口的非重置增量仍可逐步合并，不因连续运行和高延迟而等到静默才显示内容。历史重置只要求下一次读取完整窗口，不清空当前消息或改写在途请求的含义；新窗口成功后才替换，同一叶节点的完整窗口不缩减已加载历史。
6. 发送经过 Go 鉴权，优先转给已注册且进程存活的同一原生 owner；没有 owner 或确认原进程已退出时，才静默创建并复用后台 worker。原实例存活但控制请求失败时返回错误，不另开执行器，也不重放消息。普通点击发送仍为引导：原生 owner 使用 `deliverAs: steer`，后台 RPC 运行中使用 `streamingBehavior: steer`。仅在原生 owner 明确提供 `canQueue` 能力、已连接且主任务运行时，长按发送打开小型 Popover，点击“排队”单独提交 `delivery: followUp`；Pi 进程内的 `remote-queue.ts` 先持有待发送图文，以独立 UUID 标识每项；在成功的 `agent_before_settle` 边界逐条交给原生 follow-up。原生扩展 API 没有逐条撤回操作，因此不提前塞入不可撤回的原生队列，也不通过清空再重建队列模拟撤回。服务端在投递前复核 `canQueue` 和 `queueRevision` 能力，未更新的 owner 明确拒绝排队而不降级为引导；不同时引导、不因排队启动休眠执行器，也不通过排队改变当前设置或执行扩展命令。发送中只通过发送按钮展示进度，投递快照暂存在内存，不插入临时会话消息。网页排队项通过 `/api/session/queue` 单独读取，在输入框上方显示可展开的单行摘要、取回编辑及取消入口；状态快照只携带队列修订号和数量，不携带图文。长按和触摸菜单操作保留正在编辑的 textarea 焦点，键盘操作仍可聚焦菜单；浮层随 visual viewport 调整。待发送图文只在 Pi 进程内存中持有，网页刷新、导航、Go 重启与扩展重载不清空它；原生进程退出后不恢复。停止或失败不继续投递，待发送项仍可取回／取消，下次任务成功结算才继续；投递异常项保留错误且不自动重发。每会话最多 100 项、总 JSON 不超过 64 MiB，达到上限明确拒绝并保留输入。取回先按原 UUID 下载完整图文，再请求原子撤回，成功后才切回编辑，当前图文草稿独立暂存；撤回失败或回执丢失时保留原文恢复项并提示结果待确认，不自动重发。已开始投递或被其他客户端移除时拒绝撤回，不影响其他队列项。收到 accepted 表示 Pi 已接收本次投递，普通发送的快照随请求结束释放；排队项由原生持有至投递或撤回，无需用户核实落盘或手动清理；这不代表模型已处理或任务已执行。只有失败或未确认是否成功时，草稿模块才保留恢复项，由共用输入组件上方的 `SubmissionRecovery.svelte` 显示无边框单行提示与“重新编辑”入口；展开后可读取、复制完整原文并通过临时 Blob 链接离线保存图片。重新编辑不发请求；输入框已变更时先将当前图文独立暂存，再切换到原文，可通过“继续编辑”切回，不拼接或覆盖下一条。草稿身份和编辑版本共同区分原文仍在输入框与另一份草稿，同文重新编辑和新任务向会话交接也不混淆。历史中的同文记录、图片数量或 Pi 追加的图片尺寸说明均不参与投递确认。恢复项不写 JSONL，也不自动重发；逐条忽略或丢弃需要确认，只移除对应内存内容，不取消 Pi 消息、不清空当前草稿，也不修改或重建原生队列。恢复项、暂存草稿与输入草稿跨客户端导航保留，新任务首条消息复用同一投递入口，失败后打开已创建会话时一并交接。

首页和抽屉按原生会话头的完整项目路径分组，不合并不同父目录下的同名文件夹，但不展示绝对路径。项目按名称自然排序并以路径作稳定的同名次序，项目行点击展开，右侧提供当前目录新建（SquarePen）。会话固定按原生创建时间倒序排列，同时间按 ID 稳定排列；完成、工具输出、已读、改名和归档恢复都不改变创建次序，不提供手动排序。Go 在 `pi-web.sqlite` 的 `session_management` 中按原生 UUID 持有会话归档状态，在 `project_management` 中按完整目录独立持有文件夹归档状态；逐条归档至空仍保留文件夹，只有显式归档文件夹才隐藏。整文件夹归档在同一事务内覆盖所有所属会话（包括未加载页）；恢复一条会话同时恢复其文件夹，但其他会话保持归档，不提供整文件夹恢复。归档目录出现新的未归档会话时恢复可见性，旧归档会话收到回复、继续或结束均不复活目录。排列与筛选先于分页，项目修订失效旧分页；搜索尚未应用时禁用“更多会话”，不混用新搜索词和旧分页游标；未读聚合不把归档记录计入常规列表。首页在当前站点记住折叠状态，搜索自动展开匹配项目且不覆盖普通折叠偏好。

长按会话或文件夹、桌面右键或 Shift+F10 打开贴近该行的原生 Popover；会话提供重命名、分叉为新会话与归档（归档行显示恢复），文件夹提供“归档断开会话”和“归档整个文件夹”。首页与抽屉的已归档图标单击仍进入归档区，长按／右键／Shift+F10 打开“归档所有断开会话”；所有入口共用手势机制，长按松手不误触导航、展开或切换视图。菜单点击外部、滚动列表或 Escape 收起；打开后第一次点击列表行只收起菜单，再点才执行。重命名使用独立对话框，优先转给原生 owner；休眠会话通过 SDK 的 `appendSessionInfo` 写入，不启动 worker，也不由 Go 拼接 JSONL。归档仅改变工作列表，保留文件、未读和执行；即刻收起菜单并乐观隐藏，独立请求允许连续操作，失败仅恢复对应会话或文件夹，不自动重放。标签页内唯一的管理模块持有归档、恢复和文件夹修订屏障，跨导航及迟到响应不复活待同步内容。同一筛选下的摘要刷新不先清空已加载会话；项目成员或名称修订变化时，后台按原加载深度重新读取并校验同一修订，准备齐后一次替换，读取失败继续保留旧列表和缓存入口。常规／归档视图的缓存同时保存分页外的当前会话定位行，切换返回不依赖网络重新展开当前项目。列表在 DOM 更新前记录可视行锚点，更新后保持位置；被移除的首行由后继条目补位，不滚回顶部。归档当前会话或其文件夹也不导航或关闭抽屉，对话与草稿继续保留。统一“已归档”入口在同一列表切换视图，按文件夹分组、搜索覆盖未加载会话，展开后按页读取并在接近页尾时继续加载；点击一条先恢复再打开原对话，不创建执行器，实际发送仍走原生 resume。

批量归档断开会话通过 `POST /api/sessions/archive-disconnected` 提交，可选完整项目路径限定文件夹，不传则覆盖全部常规列表；不受浏览器搜索、折叠或分页限制。Go 在写入每条归档前重新检查自己观察到的 Pi 连接状态，只选择未归档且断开的会话，已连接的运行、空闲和未知状态均跳过；浏览器离线或 SSE 中断不参与判断。所有归档写入同一事务，失败全量回滚，不修改文件夹归档状态，清空后仍保留目录。前端请求期间禁用重复及交叉归档／恢复操作，菜单即刻收起，但仅在服务端成功返回后按实际归档 ID 隐藏行，避免隐藏已重连而被跳过的会话；共享归档模块持有请求、错误及修订屏障，跨导航和迟到响应仍有效，失败不自动重放。

首页底部仅有单行新任务入口，点击后同步挂载全屏编辑器并聚焦输入，模型、思考与速度只在完整输入区出现。项目选择器优先平铺已有项目，点击即选中；路径输入、主目录／磁盘快捷入口与目录浏览统一收在默认折叠的“系统路径”内，展开后才读取目录，确认后使用所选文件夹。它浏览电脑上的已有目录，不创建目录，不限于近期会话。模型选项通过 Pi 自身的 ModelRuntime、SettingsManager 与能力函数读取，不创建执行器；注册于扩展、尚不可知的默认模型仍交给 Pi 决定，不替换成网页猜测的回退模型。首次发送才创建会话、连接 worker、应用所选设置并提交图文；设置或发送失败保留草稿与已创建会话身份，转入该会话可继续处理。新任务与已有会话共用输入组件；显式模型／强度选择由草稿持有，不被迟到的默认值覆盖，发送时冻结本次设置；草稿不落浏览器持久存储；最后实际发送的项目独立保存为当前站点偏好。草稿模块按提交时的编辑版本清理本次文字，不以字符串相等判断用户是否重新编辑；发送期间新增的文字和图片随首次成功投递交接到目标会话，不留在已关闭的新任务编辑器中。用户已离开该编辑器时，迟到回执仍完成数据交接，但不抢回当前路由。

会话页点击左上角或在页面非编辑区域单指右滑打开全屏模态抽屉，覆盖整个可视宽度，高度随键盘缩小并保留安全区；抽屉内左滑返回对话，不离开当前会话。两边均宽松识别横向位移，允许明显斜滑、短滑和起手先反向再转回，不要求接近水平，也不因首个采样方向丢弃整次手势。按钮、链接、代码和表格不再按标签整块禁用；只有确实还能沿本次方向横向滚动的内容才优先使用原生滚动。浏览器接管纵向滚动前持续观察，识别后实时跟手并保留触摸事件，滑动时遮罩同步变化，松手按较短距离／速度完成或回弹，取消、多指和拖回起点恢复原状态。文本编辑、已有文本选区、其他弹窗和已由浏览器接管的滚动仍保留原生操作。顶部只有一行搜索、活跃筛选铃铛、已归档、SquarePen 新建和关闭图标，不再单列标题、新建按钮或搜索栏；点击搜索在同一行展开输入框，并在原点击中同步挂载、聚焦和将光标置于末尾，保留移动端唤起键盘的用户激活。铃铛在全部与活跃会话之间切换并高亮开启状态；活跃是未归档且有未读结果，或原生已连接并处于主任务运行、子任务运行、待你处理之一，不根据最近访问或文件时间推断。Go 在项目聚合、当前行定位与分页之前统一筛选，活跃项目默认展开，SSE 中的运行、连接与未读变化触发限频刷新。全部／活跃／归档分别缓存和保存滚动位置，全部与活跃共用搜索，关闭重开保留铃铛状态；已读空闲的当前会话不强行插入活跃列表。切换筛选或应用搜索时取消旧列表读取，迟到响应不能覆盖新视图。归档区仍在同一抽屉内，用返回按钮回到此前的全部或活跃列表；常规与归档分别保留搜索词，不改变当前对话或草稿。搜索词绑定到共用列表，由列表唯一持有防抖与筛选规则；关闭重开保留非空搜索，但不自动聚焦输入框。搜索、分页、未读和运行状态复用首页会话列表。标签页只建立一次全局 SSE，切换会话不关闭它、不使已有运行观察失效，也不重复下载全局快照或项目摘要。进入会话界面时以低优先级预加载项目摘要，其他文件夹默认折叠，点击后才加载会话，不自动打开最近会话；抽屉关闭只隐藏，切换会话也不销毁抽屉或列表；搜索词、活跃筛选、显式展开项目及已加载分页跨会话保留，因此再次打开不等待网络，对话也继续更新。每次打开返回常规视图，自动临时展开未归档的当前会话所属项目并将该行滚动到列表可视区，不覆盖折叠偏好；当前会话在分页外时随列表额外返回一条定位摘要，不占分页偏移、不读取正文。已有搜索保留，当前会话被搜索排除时不清空搜索或插入不匹配行。全局列表刷新合并并限频，状态增量直接更新已加载行。点击当前会话、关闭按钮或 Escape 收起抽屉，保留草稿、附件和阅读位置；选择其他会话才导航。浏览抽屉不确认对话中新到达的结果，收起后恢复精确已读确认。

界面以无边框内容流呈现，没有重复角色标题或消息分隔线。思考和工具使用 28px 紧凑行、较小字号和次要色，思考仅显示图标、Markdown 单行缩略和展开箭头，不重复显示“思考”标签；完整正文仍在展开时按需读取。正文、思考正文共用安全 Markdown，支持 GFM、五类 `[!NOTE]`／`[!TIP]`／`[!IMPORTANT]`／`[!WARNING]`／`[!CAUTION]` 提示块与 Mermaid 围栏；图表使用严格模式、按需执行渲染，长图只在内部横向滚动，语法或加载失败保留源码。原始 HTML 转义，正文中的远程图片仍只是链接，思考缩略中的链接不生成嵌套交互控件。正文与 Commentary 使用正文色、正文行高和独立留白，形成主次。工具名、单行摘要、状态图标和展开箭头在窄屏内保持横向排列。展开信息、长草稿、技能候选和多图片不应把发送/停止控件挤出可视区域。输入框根据内容、自动折行和宽度变化自动增高或收缩，输入卡片（含附件和操作栏）最多占当前可视高度的一半，键盘弹出时同步收紧，达到上限后只在文本框内滚动；发送清空和技能补全也同步高度。新任务与已有会话共用 `ComposerCommands.svelte`，输入框上方固定“技能／命令／Prompt”三个触控入口；点击向上展开可搜索、滚动的浮层，不挤占输入、发送和停止控件。浮层在视口变化与 Svelte 布局提交后重新测量入口位置，键盘弹出、收起及布局视口同步缩小时仍紧贴入口上方，不用更新前的位置定位。选择技能、模板或扩展命令只填入命令并保留已有正文与图片，不自动发送；`/` 仍仅触发技能补全。新任务按所选项目目录、休眠会话按原生 CWD，通过 `/api/commands` 只读发现已安装的全局、已信任项目和包技能及 Prompt 模板，沿用 Pi 的信任、筛选与重名规则，不写入信任决定，不为读取候选创建会话或执行器；已有实例返回原生已加载的技能、Prompt 和扩展命令目录，存活实例读取失败不退回磁盘猜测。切换项目取消旧读取并清空旧候选，迟到结果不覆盖当前项目；同一目录的原生实例变化时保留已有列表至新目录返回，但期间不允许选择旧命令，断网不清空已加载目录。`/` 命令候选显示全部匹配的技能，不截断数量，在限高辅助区内滚动浏览；仅显示名称，不展示说明正文，名称单行省略，点击只补全命令，不自动发送。连接提示、技能候选和附件处于独立可收缩辅助区，不得挤走输入框与发送/停止控件。会话输入框编辑时同时隐藏标题栏与会话信息条，收起软键盘或焦点离开后恢复，不以失焦代替键盘收起。会话界面唯一持有焦点、键盘可见性和本次指针操作，并由它们派生顶栏布局，不影响首页或新任务编辑器。软键盘通过同一宽度下未遮挡高度与当前可视高度的差值判断，超过 150px 视为键盘遮挡；保留未遮挡高度以覆盖 `interactive-widget=resizes-content` 同步缩小布局视口的行为，按 visual viewport 的 scale 归一化，避免把浏览器栏小幅变化或缩放当成键盘。观察到软键盘后，收起与再次弹出都独立于 textarea 焦点；未观察到软键盘时沿用输入聚焦的布局。若恢复顶栏发生在指针操作中，等本次 click 完成或 pointercancel 后再恢复；触摸浏览器的兼容 click 可能晚于 pointerup，不能在 pointerup 的计时任务里提前恢复，避免正文按钮移位而吞掉点击；Tab 切换焦点则直接恢复。腾出的高度留给正文阅读区，输入卡片仍保持半屏上限。正在阅读历史的人不能因更新、顶栏显隐、输入框增高或键盘变化被强制拉到底部。

## 弱网与本地交互

同源首页和会话链接使用客户端导航；外部链接、下载和预览仍使用原生链接。访问过的会话先显示内存中的正文和阅读位置，再用原游标增量同步。列表／会话视图缓存最多八项、合计约 64 MiB（按 JSON 字符数乘二估算，不是浏览器堆上限）；同一会话的消息窗口与已展开的工具／思考正文共用一项和字节预算，已加载块按会话、entry 和原生索引缓存。返回会话后可离线再次展开缓存内正文；同版本不重新下载，版本变化才读取，迟到的旧版本不能覆盖新正文。更新等待或失败期间继续展示已读正文并说明状态；过大的块不挤掉自身消息窗口，超限缓存仍按最近使用淘汰。未发送的文字、图片、异常投递恢复项与暂存草稿单独按会话保留，不随视图淘汰；导航期间收到回执仍只清理本次提交的内容，不能抹去新写的草稿。内容不落 localStorage、IndexedDB 或 Service Worker，刷新页面后重新读取。缓存不恢复执行状态或控制权限；导航沿用仍有效的页面级运行观察，不把切换会话当作断线。真实连接失效后，只有本次观察中新取得的原生快照可以恢复状态与权限。

阅读位置与实时跟随由 `remote-reading.svelte.js` 分开管理。前台位于末尾时跟随生成，上滑或选字即暂停；切 App、锁屏、切会话再返回停在离开时的旧位置，即使离开前在底部，也不跳过期间新增内容。键盘、图片、工具、Markdown 和迟到响应改变布局时保留提交当时的可视段落／文字偏移。主动滚回底部、点击向下箭头或普通发送明确成功才恢复跟随；排队、失败、编辑草稿不跳转。书签与有界正文缓存独立，以 `pi-web:reading` 在当前 origin 的 localStorage 最多保存 128 个会话的消息 ID、块索引及其展开状态、段落／字符坐标和屏幕偏移，不保存任何正文、草稿、图片或运行事实，不跨设备同步；存储拒绝时仍保留当前页面内存中的位置。刷新、系统回收或正文缓存淘汰后，`/api/session?around=<entry>` 直接读取书签附近的有界窗口，`next` 表示尚未加载的后续，向下阅读通过 `forward` 按页补齐；跳到最新直接读取尾窗，不扫描或下载全部中间历史。工具和思考的坐标以原生块为范围，与其他块的展开状态无关；恢复时只重新展开、按需读取书签位置原先已展开的块；折叠摘要保持折叠且不读取全文，正文未到达前不以折叠摘要覆盖原坐标。状态和已读仍独立同步。书签不在当前分支时沿原生父链定位最近共同前文；书签仅额外保留最多五个前文消息 ID，原消息被删时优先定位仍存在的前文，消息变空时沿活动分支向前寻找可读内容，均不跳到末尾。尺寸或正文高度变化引发的滚动不视为用户操作，避免键盘、布局及向下箭头显隐误关跟随；临时网络失败保留旧内容和书签，不当作失效。

标签页可见且在线时，前台 HTTP／控制结束后空闲约 1.5 秒开始逐页补取缓存内近期打开过的会话；慢速网络延至约 5 秒，省流模式不自动预取。全页最多一个后台历史请求，前台读取、发送、导航、离线或隐藏页面会中止它；失败静默退避，不抢前台带宽、不确认已读、不创建执行器。单会话自动预取的消息窗口约 8 MiB，且不能驱逐任何已有缓存或改变最近使用次序；达到预算停止，主动阅读仍可继续。后台只取普通消息与工具／思考摘要，不提前取折叠正文或图片；仅已渲染阅读范围内的图片控件按接近视口的时机加载缩略图。

缓存范围与渲染范围分开：后台补到的历史先留在消息窗口内存，不立即挂载其 Markdown、代码、图片控件或操作按钮。向上滚动至已显示范围顶部约两个视口（至少 600px）内时，先按每批 30 条显示缓存历史，缓存不足才请求下一页；网络追加沿用服务端窗口预算。只有主动翻看的范围进入 DOM。提交历史时按当前可视消息与偏移保留锚点，不使用请求开始时已过期的滚动位置；导航也在旧页面移除前保存锚点和显示起点。保留手动加载按钮用于重试与无法滚动的短窗口，失败不清空已有历史。

读取请求每次包含正文下载在内限时十二秒；网络错误和可重试 HTTP 状态先做两次带抖动的退避重试，刷新协调器在持续故障时继续有上限地退避。已有正文和列表不因失败清空，切换会话会取消旧刷新。鉴权和确定性业务错误不自动重试。发送与其他控制请求限时四十五秒，绝不由请求层自动重放；丢失响应时保留草稿并明确结果尚未确认。发送错误由会话输入状态持有，正文刷新成功不能将其清除；读取错误只由成功读取清除。发送与控制成功不另设文字回执提示，由正文、按钮及设置的实际变化反馈。

浏览器 SSE 每十五秒接收传输心跳，四十五秒无任何事件时重建连接；离线立即使运行状态未知，网络恢复或返回前台时恢复失效连接，并补取正文和状态。该截止时间只判断传输可用性，不推断 Pi 是否完成或实例是否存在；重连及迟到 HTTP 仍遵循运行状态观察代次。实时流断开只提示实时更新连接状态，不显示桥接错误，也不阻止独立的 HTTP 发送。用户不需要单独启动执行器；真实发送或控制失败才显示对应错误。

## 界面刷新与静态资源

前端继续嵌入 Go。页面只在用户点击首页顶部刷新图标或会话顶部“…”菜单的“刷新界面”时主动整页刷新；两处共用 `remote-refresh.svelte.js` 的唯一动作。不检测或提示界面新版，不根据 Worker 安装、控制器更换、SSE 重连、返回前台或计时器刷新文档。新界面在显式刷新或下次页面加载时生效，不影响原生 Pi 执行。

手动刷新请求单飞，先在十二秒截止时间内确认当前 HTML 可完整读取，再重新检查全部内存草稿、附件、待应用设置、异常投递恢复项和暂存草稿，必要时统一确认丢弃；异步预检期间仍可编辑，新输入也包含在确认内。未结束的控制请求禁用刷新，预检期间新开始的控制也取消本次导航。取消或网络失败保留原页面和内容，错误只显示文字，重试仍使用顶部同一入口。资源懒加载失败只局部降级并提示，不自动刷新。浏览器原生刷新／关闭保留条件式 beforeunload 保护，不建立持久恢复副本。

`remote-worker.js` 只在页面启动时注册同一个 `/sw.js`；浏览器独立管理 Worker 更新。没有主动 `skipWaiting`、跨标签页投票、输入冻结、SSE 暂停或激活计时器。已连接旧 Worker 的窗口未关闭时，新 Worker 维持原生 waiting 状态，不因某一标签页刷新而替换其他文档。

`vite-plugin-pwa` 的 injectManifest 继续提供内容哈希 JS/CSS 清单，Workbox 只预缓存公开静态资源，不缓存 HTML、API、会话、草稿或图片。旧 Worker 和 waiting Worker 使用同一静态预缓存；哈希资源的兜底路由可按原 URL 忽略预缓存修订参数读取其他已安装版本，使手动加载的新页面不受旧控制器资源表限制。旧资源只在浏览器原生允许新 Worker 激活后由 Workbox 清理，不因发布、手动刷新或 waiting 安装清空。通知订阅、去重和续订保留原数据库与范围。

## 应用名称与安装身份

`internal/server/app_name.go` 唯一拥有主机名回退、名称校验、SQLite `pi-web:app-name` 设置和持久化修订号。`GET/POST /api/app-name` 沿用鉴权、Origin 检查与不重放的写入规则；空名称恢复主机名，保存成功后才广播全局 `app-name` 事件，存储失败保留原设置。配置不进入源码或环境变量。

HTML、登录页和公开 manifest 都读取同一名称。manifest 由静态图标／安装参数模板动态生成 `name` 与 `short_name`，保持原 `id`、`start_url` 和 `scope`；名称不参与安装身份。`remote-app-name.svelte.js` 统一接收保存回执与现有全局 SSE 的初始／后续事件，按持久化修订号拒绝迟到响应，更新页面安装元数据并请求浏览器重读 manifest，不替换文档或操作 Worker。首页标签页名称随设置更新，会话标题仍由原生会话拥有。

`AppNameSettings.svelte` 为手机与 PC 共用同一“更多 → 应用名称”对话框，读取期间的新输入不被迟到结果覆盖，取消、读写失败或离线保留原设置；修改不创建执行器、不清除聊天草稿。手机桌面图标名称的实际更新由系统／浏览器管理，不承诺立即生效。

## 恢复与刷新诊断

页面自动将诊断元数据提交到同源、沿用现有鉴权与 Origin 校验的 `POST /api/diagnostics`，不提供手机导出入口。服务器写入 `pi-web/diagnostics/browser.jsonl`，单文件最多 4 MiB，保留当前文件和两份轮转备份，总计约 12 MiB。按服务器接收时间、浏览器时间、稳定设备身份、页面／前一页面身份及构建哈希定位事件；记录前后台与冻结、导航类型、浏览器提供的 discard 标记、手动刷新预检及失败、Worker 注册、SSE 重连、缓存淘汰、历史读取来源、游标散列、代次和条数。服务端只接收已知事件及白名单标量字段，不记录正文、草稿、图片、项目路径、令牌、完整 URL 或原始错误文本。

普通事件每秒合成不可变批次、约五秒低优先级上传，返回前台／上线立即补传；隐藏、冻结、离开和主动刷新前同步保存元数据并尝试 keepalive 上传。待发送批次最多 30 条事件，通过 `localStorage` 中的 `pi-web:diagnostic-outbox:` 跨刷新暂存，总量不超过 64 批／约 256 KiB，并在使用时清理七天前批次；服务器确认后即删除，不保留手机端诊断档案。存储不可用时使用同样有界的内存队列，失败静默退避至最多约一分钟。上传不经过聊天请求／控制计数，也不记录自身失败，不能触发更新、改变运行状态或阻塞输入。多个页面可安全补传同一不可变批次；服务端有界去重，重启或回执丢失后可能重复落盘，按设备、页面与事件序号辨认同一事件。诊断元数据不是会话内容缓存，不改变草稿仅存内存的规则。

`page.reload` 是唯一手动刷新动作的事前证据，原因固定为 manual；新文档 `page.start` 带前一文档身份和导航类型。没有主动刷新记录不能单独证明系统回收；只有支持的浏览器明确报告 `discarded: true` 才能确认 discard，其他情况结合页面生命周期及构建变化继续调查。同一页面身份下的 `session.read`／`session.commit` 则区分普通增量、历史分页、服务端 reset 和真正完整窗口读取，避免把三种现象混为同一种刷新。

## 原生记录与窗口

`Cache.OpenContent` 缓存身份、父链、字节范围、角色、结果和工具引用，不缓存正文。冷索引仍读取并验证 JSONL，但不构建历史正文、思考、工具参数或图片对象。只有没有原生名称时才读取有界的首条用户前缀作为回退名称。

空文本与无可读正文的思考不投影为显示块，保留其余原生块索引；Markdown 入口也允许缺失文本，避免单条空记录导致整个页面白屏。内联技能扩展将用户输入保存为 `custom_message`／`inline-skills` 而非普通用户记录；`sessions` 统一将 `display: true` 的这类记录投影为用户消息，从 `details.blocks` 读取技能名称、从 `details.userMessage` 读取完整提问，不展示 `content` 中注入的技能指令。窗口、历史、分享和消息分叉共用该身份与正文规则；仅技能调用也保留命令名称，隐藏记录和其他自定义通知不因此进入正文。窗口沿原生 `parentId` 选择活动分支，目标是 30 条消息、约 64 KiB；单条长回复保持完整，预算不是正文截断器。工具结果更新对应调用，不另造助手消息。记录替换、截断或原生叶节点尚未落盘时返回可重试错误，而不是拼接错误内容。已连接运行时的空叶节点代表已知空根，不能与没有运行时覆盖混淆。

文件监听只负责内容失效，不代表执行状态。新项目目录中的首个已存在会话也必须能触发更新。监听不可用时才使用内容轮询。

## 运行状态与确认

Go 通过原生 owner 文件定位地址，并保持一个经过鉴权的快照订阅。快照首先原子提供当前状态，再推送修订。浏览器与 Go 不通过文件时间、标题字符串、输出静默或活动文件判断执行是否完成；没有活动文件心跳、运行状态 TTL 或浏览器状态轮询。

owner 文件包含 PID、端口、原生 UUID 和随机令牌，控制时校验原生会话身份。连接关闭立即变为未知。`unknown` 表示缺少运行事实，不代表会话损坏；终端与网页通过 `shared/session-presentation.js` 使用同一套显示含义，分别绘制醒目的 emoji 与 Lucide SVG。终端 emoji 映射由 `.pi/extensions/lib/title/format.ts` 持有并随扩展重载，状态含义仍由共享模块解析；标题用 ⏳ 表示主任务运行、🧩 表示子任务运行、❗ 表示待处理、⚪ 表示普通空闲、✅ 表示成功完成、❌ 表示失败、⏹️ 表示停止、❓ 表示状态未知，未读另加 🔵，不覆盖状态图标。列表与会话头只显示图标：未连接 Pi 为中性断开插头，已连接但运行状态不可用为问号圆，网页实时流断开为断网图标，运行中为旋转圆环、子任务运行中为层叠图标、待处理为警示圆；普通空闲为空心圆，只有原生成功结算收据才显示勾，失败为叉、停止为方块。未读独立显示圆点，不覆盖运行或结果图标；在任一前台入口确认同一结果后共享清除。连接失效优先展示网页实时连接中断；传输重新打开但尚未取得本次运行事实时显示状态暂不可用，不显示未连接 Pi。原始快照保留，只使观察失效，不把网页传输变化改写为 Pi 的断开事实。文字含义仅供悬停提示和读屏；不把历史记录推断为空闲或完成。HTTP 与 SSE 共用带观察代次的合并规则，旧 HTTP 响应不能覆盖更新的 SSE 事实，断线前开始的响应不能重新恢复“在线”状态。

SQLite 中的确认键是原生会话 UUID 与精确结果 ID，不是时间水位。Pi 可以在 Go 停止时独立写入确认；Go 可以在没有执行器时确认历史结果。切换分支、重连或重复快照不会制造新的完成结果，也不能用旧确认清除新结果。

主运行在 `agent_settled` 结束，而不是中间的 `agent_end`。完成候选必须对应本次产生的新可读结果，并绑定本次观察到的子任务身份。只有原生 idle、已知零活动子任务，以及相关提供方明确成功的终态证据同时成立，才允许完成；失败/停止会取消候选，缺少证据保持未知。候选与依赖在扩展重载时保留，不另建子任务执行账本。

网页资源重载通过 `POST /api/session/reload` 携带已观察到的 `instanceId`，沿会话控制串行化交给当前 owner，不创建执行器。原生端拒绝过期实例、主任务／子任务忙碌、待处理交互、原生排队和其他在途控制；实际重载由 `/pi-web reload` 命令上下文执行，不将 `/reload` 文本交给模型。扩展关闭时仅保留本次重载的 HTTP 回执连接，不等待它关闭，其他旧连接释放；原生重载完成后才返回成功，失败不重放。新运行实例重新发布快照，网页按新实例身份失效候选目录；图文草稿、页面和原生网页队列保持不变。

原生阻塞对话框以其原始身份保留至原客户端处理。扩展重载不伪造确认，也不把未解决对话框当成空闲。

## Worker 与进程

浏览、状态查询、下载和确认均不创建 worker。`workers.Manager` 统一校验注册、原生 UUID 与 PID，选择现有终端或后台 owner；只有明确新建或实际发送才允许创建后台进程。同一会话的创建、设置与命令投递串行化，最多一个受管理的 worker。注册损坏、进程存活无法确认、原实例暂时不可达，或已知存活实例的注册暂时消失，均返回错误而不替换；命令不自动重放。

无已知实例或确认原进程退出后，下一次发送以 `pi --mode rpc --session <原文件>` 创建新实例。沿用原生 UUID 与 JSONL，由 Pi 自己恢复分支、压缩和模型上下文，不保存另一份活动叶节点或恢复副本。这是原生 resume，不恢复旧进程内存，也不承诺重放未完成工具或不确定的外部副作用；没有单独的继续按钮或接口。

扩展只在本次原生会话启动时尝试注册。已有 owner 时，后来打开的实例不登记控制端点；owner 离开后它也不会自动升格，避免把旧内存分支重新宣布为当前状态。这不限制该实例原生的终端操作或写入，也不构成多实例执行锁。

后台 Pi 的标准输入与输出由独立 Node 宿主持有，Go 通过经随机令牌鉴权的回环 TCP 使用 RPC。Go 关闭只释放自己的客户端连接，不向 Pi 发送 EOF；Go 启动后继续通过原 owner 接回同一 PID。宿主注册位于 `pi-web/workers/`，原子竞争且只在确认旧宿主 PID 退出后替换；启动期间重启 Go 也不能重复创建原生进程。宿主持续读取原生输出，并隔离各客户端的命令回执，断开的请求不会重放。

宿主是连续空闲回收的唯一拥有者，Go 停止期间也继续工作。计时从已连接的原生 idle、主任务停止和已知零子任务同时成立时开始；运行、未知、断线或活动子任务打断连续区间，普通查询不延长计时。连续空闲五小时后先由属于该宿主的原生端确认无运行、排队或控制请求并拒绝后续投递，再通过 EOF 有序退出；不关闭终端 Pi。原生退出时宿主也清理自己的注册并退出。Windows 宿主隐藏、独立启动，macOS 启动配置不收割其进程组，systemd 启动的宿主进入独立用户 scope。

首页和会话顶部仅显示静态标题，没有下拉箭头或切换入口；会话标题最多两行，不显示重复的 Pi Web 或电脑名称／地址。新任务编辑器仅保留项目选择，不显示电脑名称／地址。非输入状态下，标题栏下方显示单行会话信息条：项目文件夹（Git 分支）、↑累计输入／↓累计输出、CH 缓存命中率，以及环内上下文占用百分比。窄屏仅省略过长的项目／分支，指标不换行。圆环只在顶部显示，数值取整、弧长使用原始百分比并封顶 100%，超过容量时环内仍保留真实的超额百分比；完整上下文 token／容量保留在提示中。输入输出由原生 `SessionState` 按 Pi 页脚同一范围聚合会话的 usage、助手／工具消息及压缩／分支摘要用量；Go 仅转发 `usage`，浏览器只格式化为 k，不从正文估算。CH 沿用原生快照，上下文来自 `getContextUsage()`；严格超过 70%／90% 的原生占用值时，圆环进度与环内文字一起显示警告／危险色，浅深色共用语义色板。压缩后未知、未连接或断线显示问号与空进度，不保留旧值或伪装成零；缺失原生 `usage` 时输入／输出同样显示问号，网页服务更新不能替代原生扩展重载。更多菜单提供应用名称、两种上下文分享、通知和刷新，输入区不再绘制上下文圆圈。

休眠历史会话也可先选模型、强度与速度，读取选项不创建执行器。选择由会话草稿持有，发送时冻结并随消息提交；Manager 在同一投递区间内先应用设置再发送正文。失败保留设置、文字与附件，未显式选择的字段继续沿用 Pi 恢复出的会话设置。已有实例的直接设置仍实时生效。

## 手动关闭进程

会话顶部“更多 → 关闭进程”只在原生已连接且可控制时可用，发送和关闭提交期间禁用重复操作。确认明确提示强制结束 Pi 及其子进程、任务中断和进程内排队消息丢失；取消不发请求，关闭不清除页面草稿或已保存会话。

`POST /api/session/shutdown` 沿用鉴权、Origin 检查及不重放的控制请求规则。Manager 在同一会话串行区间内选择已有 owner，不为关闭创建 worker；原生 `state` 回执必须匹配 UUID，才由系统终止登记 PID 的进程树。Windows 使用指定 PID 的 `taskkill /T /F`，Unix 递归结束其子进程与 Pi 本身，不按名称批量关闭。确认 Pi 已退出后释放客户端连接和 Manager 的缓存引用；后台宿主观察原生退出后自行清理并退出。网页服务、其他会话和终端外层 shell 不关闭。状态仍由实际连接断开更新，不提前伪造断开；下次发送沿用同一 UUID 和 JSONL，通过既有原生 resume 启动新进程，不恢复旧进程内队列。

## 会话详情与手动压缩

会话顶部“更多”和输入区“命令”列表均提供会话详情与压缩入口。`GET /api/session/details` 从原生头及内容索引返回 UUID、完整 JSONL 路径、工作目录、创建时间和当前活动分支最后一次压缩摘要；身份不使用网页路由的文件名，也不为读取启动执行器。复制复用正文的剪贴板动作，保留逐项失败反馈。

`POST /api/session/compact` 只转给已有 owner，绝不为压缩启动休眠 Pi。`SessionState` 唯一持有手动压缩进度与错误，在原生 idle、已知零子任务及无原生待处理输入时允许提交，自定义保留要求原样交给 `ctx.compact()`，不把 `/compact` 作为模型提示词发送。回执只表示提交；进度通过现有快照／SSE 提供，摘要完成后按需从原生 JSONL 读取，不塞进状态广播。原记录保留，不清除网页草稿，关闭弹窗也不停止压缩，失败不自动重放。思考等级选项继续由原生模型能力提供，支持的 `max` 显示为“最高”，实际设置再次由原生能力校验。

## 独立会话分叉

列表长按菜单的“分叉为新会话”复制当前活动分支；用户气泡长按（桌面右键／Shift+F10）的“从这里分叉”和助手正文下方的 Fork 图标，均保留到该原生消息（包含该消息），不采用原生 `/fork` 排除用户提问并回填编辑器的语义。用户气泡不再绘制底部操作行，长按菜单提供复制与可用的分叉；移动端气泡使用自定义长按，不弹原生选字菜单，桌面拖选仍保留。气泡内链接和图片等交互控件保留自身行为。完整助手回复下方左对齐放置复制和可用的 Fork 图标，不在右侧预留空间或覆盖正文；首个图标左缘与正文对齐，触控区向左外扩而不形成可见缩进；两个图标保持紧凑间距，保留互不重叠的 44px 触控区。工具穿插说明不再绘制底部操作行：相邻正文块合并为一段可复制内容，复制图标紧随该段正文末尾，只留一个自然空格，不叠加左侧内边距；行尾不足时自然换行并与正文左缘对齐，仍保留向右延伸的 44px 触控区且不开放分叉；列表、代码等块级结构保持原排版，按钮在块后、工具前。`Markdown.svelte` 只负责尾随内容的排版，复制与失败反馈仍由 `CopyAction.svelte` 拥有。复制仅取对应正文的可见 Markdown 源文，不包含思考、工具、图片字节和模型专用尺寸提示，离线也可使用；成功显示勾选反馈，权限失败就地提示并可重试。助手正文继续保留原生选区与分享。所有消息分叉入口共用会话级忙状态，避免同时创建多个分支。Pi 没有直接重新生成回复的 RPC，自动重试仅针对暂时失败；本界面不把重新发送提示词伪装为重来，也不展示无效按钮。`sessions` 唯一拥有断点规则：消息入口只开放用户消息与有可读内容的完整助手回复；路径上的工具调用与结果必须完整，不能靠分叉点之后的结果补齐之前的调用。全会话复制保留截至活动叶节点的命名等原生元数据；空根、非当前分支、失效节点和未完成工具均明确拒绝，不静默退回旧位置。

完整助手回复的结束时间以浏览器本地 `HH:mm` 尾随最后一个输出，普通段落尽量同行，行尾不足自然换行；列表、代码、图片和错误保持原排版。Fork 右侧显示本轮耗时，不加入正文复制或上下文分享。`internal/sessions/window.go` 沿完整活动分支，将每条最终回复与其前方最近的用户消息（包括可见 `inline-skills` 提问）配对，以两条原生记录的 `timestamp` 之差投影 `durationMs`；工具／思考过程和请求起始时间不充当最终回复时间。尾窗、历史、书签及前向窗口共用该计算，不要求提问已经下载到页面。没有有效配对、时间缺失或倒退时不显示计时，不新增持久化账本，也不修改原生记录或运行状态。

`POST /api/session/fork` 在 Manager 的原会话串行区间内确认 owner：在线时只请求原生 `state` 获取真实 `leafId`，休眠时使用落盘叶节点。存活 owner 不可达或身份不明时拒绝，不猜测文件末尾，也不创建替代实例。Go 内容索引校验并固定具体原生 entry ID，随后用独立打开的 SDK `SessionManager.createBranchedSession` 复制根到该点的路径，不手写 JSONL，不向原运行时发送会替换会话的 RPC `fork`／`clone`。

SDK 在同目录的临时子目录完成新文件与“原名 · 分支”命名，再原子移入会话目录；中途取消不会向列表发布半份文件。新文件拥有新 UUID、创建时间及 `parentSession` 来源，保留该路径上的图文、思考、工具、压缩与扩展记录；不拷贝其他支线、网页草稿、归档、执行进程或原结果确认。正常结束清理临时目录；被强制终止时未发布的临时子目录不参与会话索引。

成功返回新会话 ID 后同页导航，输入框为空，原会话草稿、附件与执行保持原状；分叉与进入均不启动 worker，首次发送才按现有 native resume 启动。工作目录仍相同，不创建 Git 分支或文件系统副本。请求期间禁用重复操作，不自动重放；超时／网络中断提示结果尚未确认，需先看列表。用户已离开原界面或关闭列表抽屉时，迟到成功不抢回导航。

## 上下文分享

会话顶部“更多”提供“分享已加载上下文”和“分享完整会话”，点击先关闭更多菜单，再由顶层唯一 `ContextShare` 准备或分享。不要求选中文字，不再创建选区浮动菜单、拦截右键或改写原生选区；正文和输入框保留系统复制、翻译等操作。

“分享已加载上下文”同步复制当前页面内存中的消息文字（包括后台预取但尚未显示的历史）、工具摘要和已经读取的工具正文，在同一次点击中生成 TXT 并调用 Web Share API，断网也不等待请求。各 `RemoteBlock` 从会话缓存恢复已加载正文，通过只读 `loadedBody()` 提供当前可读快照；未挂载的历史块直接从会话缓存取已读正文。收起或切换会话再返回后，缓存内正文仍可分享；未读取的工具只有摘要，点击分享不另取更早历史、折叠正文或完整会话。TXT 明确标注这是不保证完整的缓存范围。

“分享完整会话”才通过经过鉴权的 `/api/session/context` 读取当前活动分支的完整会话文字，不受页面历史窗口限制，也不创建 worker。导出包括用户／助手正文、工具输入输出和压缩／分支摘要。准备和分享分为两次点击：网络读取完成后，用户点击“分享 TXT”直接调用系统分享，保留瞬时用户激活，不在异步读取后自动打开分享。

两种 TXT 均为会话上下文，不附加选中片段；不包含思考、图片原件、系统提示、未发送草稿或额外读取的项目文件。响应和生成的 File 不持久化，关闭弹窗取消准备并释放引用。仅按实际 File 检测分享能力；系统选择接收应用，网页不指定 ChatGPT，不宣称接收端已上传或发送。HTTPS／浏览器／文件类型不满足能力要求时提供下载和复制提问；用户取消系统分享不自动下载，失败保留可重试文件。

## 附件和预览

待发送图片使用临时 Blob URL 只显示 56px 缩略图与角标移除按钮，点击在页内全屏查看，离线也可预览和下载；文件名与下载仅在预览中出现，长图在预览内部纵向滚动以完整阅读。组件销毁、移除图片或切换草稿时释放 URL，原 File 仍由内存草稿唯一持有。会话图片、本地图片链接和工具结果图片统一只显示 96px 缩略图，多张可换行；点击全屏查看后才显示名称与下载，原图预览与下载保留原始字节。`read` 的单个图片文件引用与其图片结果合并为一个缩略图，使用原生结果字节并保留文件名；原生图片没有保存名称时显示“图片”。用户图文末尾由 Pi 追加的尺寸／坐标提示仅在网页正文中隐藏，原始记录、模型输入和上下文分享不改写。服务端缩略图处理封装在 `internal/server/image_thumbnail.go`，支持 PNG／JPEG／GIF／WebP、JPEG 自动方向和透明背景合成，只生成第一帧；解码前限制为四千万像素。本地图片通过 `/api/session/file?thumbnail=1` 使用同一缩略图处理，文件原件仍只在明确预览或下载时读取。缩略图不支持或读取失败时保留打开原图与重试入口，下载仍在全屏预览中，不自动退回整张原图下载。

工具结果中的附件由 `remote-files.js` 统一按来源解析：先解开 codemode 的逐行 JSON，再在每个返回对象自己的 URL 或 `Repository cloned to:` 目录下解析 Markdown 链接；`read` 正文中的相对引用跟随所读文件目录。联网结果中没有来源的相对引用不生成附件，不回退到当前项目的同名文件。GitHub 的 blob/raw 文件链接转为原始字节地址，锚点与普通网页导航不冒充文件。正文中的网络图片同样进入页内图片预览。\n\n外网附件通过经过会话鉴权的 `/api/session/file` 按需读取；缩略图复用本地图片处理，点击后才取原图，下载保留原字节。`remote_attachment.go` 唯一拥有外网读取策略：仅 HTTP(S)、不转发 Cookie 或控制凭据、不使用环境代理，连接及每次重定向均重新检查并固定公共 IP，拒绝回环、私网、Tailscale 和保留网段，单次限时十秒、最大 32 MiB。Markdown、HTML 与文本只在显式预览时读取，外网预览采用禁止脚本、同源权限、控制请求与表单提交的沙箱，文内相对资源以重定向后的来源 URL 为基准且限定在该来源；原文入口保留供登录、超限或源站拒绝时打开。外网文件不创建本地目录预览能力，也不进入持久缓存。\n\n本地文件引用按原生会话 CWD 解析，下载返回原字节和附件响应头。文件卡片采用约 34px 的紧凑单行，长名称省略且保留完整路径提示，预览和下载入口不换行、不被挤出窄屏。HTML 和 Markdown 只有明确预览时才创建随机、只读、短期能力地址，`os.Root` 限制在文档目录内并处理符号链接。

预览 iframe 使用不含 `allow-same-origin` 的沙箱，CSP 限制控制接口、表单外发和资源范围。相对 HTML 模块、CSS、JSON 与 Markdown 资源在该能力范围内读取，不共享 Pi 控制凭据。关闭、重新加载、过期、驱逐或 Go 重启使旧能力失效。私有 Pi 目录不是预览根。

## 通知

通知弹窗由页面顶层唯一实例持有，入口放在首页或会话信息菜单，打开时先关闭菜单，弹窗不受折叠与菜单项重绘影响。弹窗区分等待授权、准备通知服务、连接推送服务和保存订阅；浏览器授权与推送调用限时二十秒，超时恢复操作并提示对应步骤。用户可以停止等待；关闭弹窗、离线或组件销毁也立即解除等待并中止在途 HTTP，迟到结果不自动继续保存。浏览器的 `subscribe()` 本身不能取消，显式重试复用仍未结束的调用，不并发创建订阅。已有同 VAPID 密钥的有效浏览器订阅直接补存服务端，不能因服务端缺少记录就先注销重连；只有密钥不符、浏览器到期或服务端明确标记过期才重建。连接推送服务由浏览器直接完成（Chrome 使用 Google FCM），网页可访问不代表该通道可用，界面在此步骤及失败时明确说明。通知直接复用应用已激活的 Service Worker，不重复注册或等待新版检查；注册由独立 Worker 模块负责，更新遵循浏览器原生生命周期。通知 HTTP 请求使用可中止的截止时间，不在超时后继续后台提交，也不自动重放。`push.go` 负责 VAPID、加密投递、去重和持久重试；`push_http.go` 负责订阅接口。服务端固定生成中文通知，浏览器只提交订阅和续订信息，不上传或持久化翻译模板。升级时只清理订阅 JSON 中的旧模板，保留端点、密钥、登录和待发送事件。

只对经过验证的未读完成结果或明确待处理身份通知。运行中、后台、未知、取消和失败不能制造成功通知。身份由原生会话 UUID、结果/待处理 ID 决定，重连与分支返回不重复发送。发送前和展示前检查结果仍有效；收到或关闭通知不写已读。

VAPID 私钥保存在 SQLite，不向浏览器返回，也不在升级时替换。Apple、Google、Mozilla 推送端点采用 HTTPS 白名单并禁止跟随重定向。消息只含原生会话名称、身份与状态，不含正文或原生对话框文本。

Service Worker 不缓存会话，只保存去重和续订元数据。点击通知聚焦精确会话，不覆盖其他会话的草稿。仅关闭精确已确认结果的通知，订阅更换时迁移待投递事件。服务接受不等于设备实际收到。

## Fast 与命名

Fast 的项目/命令行/持久设置优先级、实时切换和模型适用性属于模式拥有者。网页使用版本 2 事件：`pi-codex-fast:query` 查询、`pi-codex-fast:state` 回应、`pi-codex-fast:set` 会话设置、`pi-codex-fast:changed` 失效通知。`availableModes` 表示各目标模式的能力，不拿当前模式是否生效代替它；只在目标不同时设置，拥有者写原生会话 custom entry 并在恢复时读取，不修改全局默认，也不向模型提交假命令。原来的终端 toggle 命令仍保有其原生持久设置行为。请求/回应必须同步匹配版本、requestId 和当前模型；缺失、未初始化、多个冲突回应或异步回应都保持未知，不复制允许列表或推断服务等级。

`scripts/enable-fast-state.mjs` 仅为已审阅的本地 0.1.11 源码安装这一接口，默认 dry-run；从原版或已知旧接口单向升级为同一版本 2 输出，校验目标指纹，备份后原子替换，拒绝未知修改。模型名单和服务等级规则仍只存在于原生拥有者，不在项目中复制。

标题实现来自 `pi-title-glyphs`，来源与 MIT 许可集中在[根目录第三方声明](../../../THIRD_PARTY_NOTICES.md)。命名沿用原配置路径及 `PI_TITLE_GLYPHS_*` 环境变量。命名只观察进入会话的首条有效用户消息，不依赖终端／RPC／扩展的输入来源；被命令消耗的输入和扩展通知不触发命名。可见 `inline-skills` 消息使用其原始用户正文与技能名，不摘要展开指令。先由 Pi 保存首句名称，再异步请求配置模型；纯图片等待后续文字，打开未命名历史时按活动分支补全。网页的 prompt 截取仅是读取回退，不另存名称。已保存名称不再读取开场正文；标题追加游标只读取新增命名元数据。过期模型摘要不能覆盖另一实例的手动改名。

## 外观

`theme.css` 是浅深色的唯一色板，使用 prefers-color-scheme 自动跟随系统；启动脚本只同步浏览器 theme-color，不再恢复旧主题或加载自定义主题覆盖。应用与令牌登录页共享色板。系统字体作为默认，已有明确字体偏好仍保留。输入区与浮层使用统一的圆角、阴影，全屏抽屉不留侧边空隙或圆角；图标统一使用 Lucide，动效遵守 prefers-reduced-motion。

## 鉴权与安装

令牌 cookie、请求头和登录表单沿用现有协议。浏览器危险请求校验 Origin；无令牌本地访问校验 Host，防止 DNS 重绑定。非回环监听需要令牌；只有启用令牌时才配置 Tailscale Serve。

平台安装与登录启动复用 `scripts/run-lifecycle.mjs`、现有安装器和平台服务管理/启动器。源码更新必须安装本次构建，不能仅因版本字符串未变就跳过。日常数据与配置保留，部署后验证监听、鉴权和前端产物。

源码分发不携带机器的工具链路径、服务环境、登录启动文件或用户数据。构建工具统一通过目标电脑的 PATH 发现；Git Bash 路径仅注入构建子进程，不传入安装环境。安装目标和生成启动器中的本机路径由当前 HOME 与安装参数产生，运行不依赖源码目录。

Windows 启动器启动时重新读取当前系统、用户环境，不保存安装时 PATH；PSModulePath 由各 PowerShell 宿主初始化，不从上游宿主或服务 env 覆盖。普通安装会迁移旧环境快照，即使二进制哈希相同也重新生成启动配置；同构建不重启服务，原位更新不改配置。安装脚本与生成的 PowerShell 使用带 BOM 的 UTF-8，VBS 使用带 BOM 的 UTF-16，避免系统代码页、Git 换行设置和非 ASCII 安装路径影响解析。
