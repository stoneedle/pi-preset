# 研发与复杂交互失败模式参考表

| 问题概述 | 实例 | 参考解决思路 |
|---|---|---|
| 缺乏整屏信息架构与对象归属，把复合业务降维为孤立控件平铺；暴露内部术语，以大段说明文字代偿自解释示能。 | 1. 规则编辑器平铺文字、输入框与卡片，用户看不出条件层级与归属；统一皮肤后仍是零件拼盘，无整屏操作流。<br>2. 业务界面直出“签名”“补录”“前沿”等内部术语；因缺少直观示能，堆砌长段文字解释如何滑动、点击与选择固定/范围。 | 先拿真实复杂内容构建整屏对象容器、层次与操作主线，再选具体组件；用视觉容器与操作示能表达逻辑，内部概念转译为用户任务。 |
| 按单行单组件思维分配空间，拆散强关联操作；未在小屏与动态内容下校验，导致挤压变形或零散换行。 | 1. 数字输入框独占整行，加减步进按钮被挤到下一行；三个并列参数调节器反复占用两行。<br>2. 窄屏下换行将连接词挤成孤立单字行；校验错误文字弹出时直接将同行的输入框顶偏变形。 | 按语义单元打包排版，强关联的输入与调节控件保持同行内聚；用极端长短文案、目标最小屏宽和软键盘顶起状态校验布局弹性。 |
| 以为数据能移动即拖拽成立，忽略触控形态连续性与占位预判；进入编辑态直接挤动原对象，破坏既有排版。 | 1. 长按拖动卡片时，浮层丢失完整卡片只剩标题；拖到目标区域只有细缝而不腾出占位，用户无法预判落点。<br>2. 列表项进入编辑态后就地插入辅助控件，把原先对齐的内容向右挤歪。 | 抓取什么就拖什么，浮层保持原对象完整尺寸与形态；移动中实时预览占位腾位，未释放前不改数据；编辑态以原位叠加呈现，不挤动原有布局。 |
| 低成本微调或查看动用全屏/半屏遮罩、无条件弹起软键盘或加设确认弹窗，粗暴打断用户原有的编辑现场。 | 1. 仅修改微小的计量单位即拉起全屏遮罩的底部抽屉（bottom sheet）；点进复杂编辑器未点击输入框即自动弹出软键盘，遮挡大半屏幕。<br>2. 用户未做实质修改直接退出时，界面依然弹出二次确认弹窗拦截。 | 按操作粒度匹配交互：局部微调原位切换或用轻量浮层，保留对象上下文；软键盘仅跟随显式文本输入意图弹出；无实质损失的退出直接放行。 |
| 控件视觉暗示与实际行为冲突，核心高频能力缺乏显式入口，操作失败或校验阻断时缺乏原位反馈。 | 1. 界面叉号图标直观暗示“退出编辑”，点击后却直接删除了当前编辑的节点；循环等核心操作未设常驻入口，仅藏在无提示的长按手势中。<br>2. 点击“保存草稿”或“启动”后校验失败，界面既无标红也无提示，静默无响应。 | 图标形态严格匹配行为后果；核心任务保持可见可达；每次点击均有原位成功、进行中或具名失败反馈，避免静默拦截。 |
| 设计微动效与视觉质感时缺乏物理规律或成熟作品锚点，仅凭直觉在代码中反复调参赌生成，导致质感反复劣化。 | 1. 光迹流转动效反复微调贝塞尔曲线后退化为廉价光斑，最终全盘回退至最初手绘版本。<br>2. 弹性交互动画反复修改弹性系数与阻尼函数，形变依然生硬卡顿、缺乏自然惯性质感。 | 先找成熟动效或物理规律确立时间、节奏与形变参考；若微调未能收敛，优先复用成熟动效方案或转交专业设计定稿，不靠盲调参数试错。 |
| 以静态截图打分、界面清单打勾代替端到端真实操作，掩盖手势破损、动效缺失与状态流转缺陷。 | 1. 走查报告针对静态截图大谈视觉重心，却完全漏掉卡片拖拽时坍缩为单行标题的严重手势破损。<br>2. 静态页面截图评分为 PASS，实际底部导航栏动画与动态换肤接线已在重构中静默失效。 | 以用户核心任务的完整动态操作流作为最终验收标准；静态画面只证明静态视觉，不能作为交互手势与动态状态成立的凭据。 |
| 引入新技术能力时不调研开源生态、官方推荐或既有依赖，凭直觉从零手写脆弱轮子，陷入低效修补。 | 1. 实现衣物图像分割时盲目手写颜色阈值算法，反复调参效果依然极差，经提醒后才转为引入成熟模型方案。<br>2. 实现图片预览时手写遮罩与缩放手势，耗费大量时间仍无法流畅缩放拖动，最终被迫改用 PhotoSwipe。 | 确定路线前先检索成熟开源库与已有能力；单向门高成本能力必须充分比较，仅在存在不可替代的真实缺口时自研。 |
| 孤立抠字面指令而忽视真实业务目标，靠位置挪移、生硬遮挡或边角硬塞敷衍完成，破坏整体体验与架构。 | 用户要求删减拥挤控件，实现未做层级梳理，仅把按钮机械换个位置，将把手、删除与编辑操作硬塞进边角即宣布完成。 | 先判断实现手段是否真正服务于系统目标；指令有缺陷时明确说明后果并推荐替代方案，不机械执行错误路径。 |
| 发现缺陷时不追溯至拥有该规则的源头模块，而是在自己负责的调用端堆砌转换、过滤或容错补丁，导致契约碎片化与逻辑重复。 | 1. 共享环境掉线时，恢复入口在调用层机械等待无响应的底层守护进程超时，超时后退出，未执行强杀重启。<br>2. 列表向详情页跳转时漏传参数导致入口丢失；同一业务实体的几何计算在多处调用端各自维护映射，微调后全局错位。 | 沿因果链路找到拥有该规则的模块根治，修改接口并一次性贯通所有现行调用方、删掉历史补偿；最小化完整解法的成本，而非单次 diff。 |
| 修改目标需求时未做职责隔离，随意顺手改动未经授权的周边稳定模块，导致已交付功能静默回退。 | 1. 仅需调整分类树结构，却顺手拆除了已经验证通过的“时间×次数（排除双不限）”八种限制规则组合。<br>2. 优化底栏外观样式，却在改写中丢弃了已有的动态主题换肤接线与选中过渡动效。 | 动工前明确当前任务修改边界与承接职责；只改变目标行为，周边已确认能力必须完整保留，新功能成立不等于旧能力仍在。 |
| 把历史设计稿、旧工单或过程摘要当成权威规范，无视现行代码已演进的事实；改动后未清理陈旧描述，导致旧需求反复发号施令。 | 1. 导航栏已移走资产入口并加入中央加号，但旧文档和工单仍写着“五项导航”，实施时主动改回老版五项导航。<br>2. 导航回退被指出后，旧工单中错误要求仍未清理，次日多份材料仍继续声称资产位于底栏。 | 代码是当前行为事实的唯一定真源（SSOT）；描述与代码冲突时优先修正描述；新形态上线必须清理旧实现、旧入口与旧引用，阻断污染源。 |
| 测试装置悄悄绕开真实难点换取绿灯；以堆砌低价值测试或全量矩阵掩盖核心功能未收敛，用测试数量冒充工作进展。 | 1. 界面测试辅助函数先自动收起软键盘再执行点击，避开了“键盘弹起遮挡控件”的真实交互冲突。<br>2. 核心算法视觉效果严重失真未收敛，却通过编写多项测试获得通过，并将增至32项测试作为收敛进展汇报。 | 验证条件必须保留真实失败前提，预期来自用户目标而非反推实现；新增测试服从显式授权并对准具体损失，不以测试数量作为交付成绩。 |
| 环境或依赖异常时就地停工空转、等待用户救场；或坚持必须先查明崩溃根因才允许恢复，阻塞交付路径。 | 1. 共享测试模拟器失联后，各并发任务均在等待维护窗口，无人尝试重启进程或重建容器，全线空转。<br>2. 环境进程假死时，明明可重启恢复，却因“未查清崩溃根因”被卡住，不予执行恢复。 | 区分“恢复可用”与“根治排障”；阻碍交付的环境问题在授权内优先通过幂等恢复入口重置可用；按实际影响与成本自主修、关键取舍主动问、无益果断放。 |
| 脱离当前规模与真实约束，为臆想的未来并发或极端风险设计复杂的状态机、锁或隔离机制；随意叠加临时旁路脚本，破坏入口清晰度。 | 1. 仅需确保各会话能看到最新产物，却引入设备占用排队锁和多工作空间动态销毁等重型机制，令简单调试寸步难行。<br>2. 热更构建链随意叠加多套临时脚本与旁路分支，最终只能靠编写长篇说明维持日常执行。 | 新增机制必须消除明确需求下的已知损失；优先依赖标准化工具与自解释目录构建唯一定位入口，不为未证实的风险提前买单。 |
| 分发任务或交接时未提供必备的工具权限、前置可用环境与参数边界；调用底层工具时单位混淆引发长时间挂起。 | 1. 将验收工作委派给下游，却未为其开放终端工具权限，且交付的环境本身处于假死状态，导致执行者全面卡死。<br>2. 调用系统执行工具时把毫秒值直接填入秒级超时参数，导致超时等待被放大成上百分钟的长时间无响应停顿。 | 委派前核验执行端必备工具、可用环境与完整目标约束；严格校验工具参数单位，由平台或工具层内置上限防护。 |
| 排查问题或复盘时丢失源码版本、运行时刻与隔离边界，拿新现场没有复现武断否定历史发生的真实故障。 | 1. 此前因依赖版本冲突导致构建失败，后续新状态下解析成功后，便直接得出“目前没有证据表明依赖冲突挡住了构建”并质疑原故障。<br>2. 切换独立数据库验证通过后，未核验设备主题 ID 证据，便认定配置已全量恢复。 | 技术证据必须携带代码快照、运行时间与证明范围；新快照成功不能直接否定历史失败，隔离环境结论不自动等于全量真实环境。 |
| 受到质疑时靠频繁道歉、改口附和或长篇理论公文代替实质行动；把内部开发进度、调试指标等过程噪音填入最终交付物。 | 1. 受到用户质疑后立即改口撤回原判断，连续输出无实质增量的长篇公文与认同解释，却未推进具体行动。<br>2. 把实现进度与就绪评估写进产品文档，或把开发内部指标直接塞进面向用户的界面中。 | 改变判断必须基于新证据，交付成果要落到新增结论、具体行动或明确取舍；严格区分过程上下文与交付物，不向用户输出内部排障噪音。 |
