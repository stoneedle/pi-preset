# Pi 环境维护

在任意工作目录维护 Pi 的扩展、技能、角色、提示词或共享配置时读取。唯一配置仓库是 `~/.pi/preset`，本文件中的相对路径以该仓库为基准；业务项目依赖不属于此流程。

## 定位与授权

- 读取仓库的 `AGENTS.md`，核对 Git 分支、远程和已有改动。共享内容以 [README 的来源表](../README.md#来源与入口) 为准；不把当前业务仓库或临时目录作为 Pi 定制的安装来源。
- 用户授权决定改动、提交、推送与对端操作的范围；用途或发布范围不清楚时先澄清。保留其他任务的未提交与暂存内容，仅处理获授权的改动。
- Pi 用户目录的共享配置应链接至仓库本体。使用 `node <仓库>/scripts/setup.mjs check` 验证；定位或链接不成立时停止，不另建配置副本。

## 收录与本机验证

- 单文件扩展放入 `extensions/`；完整插件放入 `packages/`，在 `settings.json` 登记相对 Pi 用户目录的路径，例如 `../preset/packages/名称`。
- 未修改的 npm 插件固定版本，全局 `pi install` 的安装声明通过设置链接写回仓库。未修改的技能在 `preset.json` 固定上游 commit 与所选目录。
- 开始定制上游组件时，将本体纳入本地维护目录，替换原版加载声明，只保留一个加载来源。凭证、机器配置、会话和运行数据留在各机用户目录。
- 文本或 TypeScript 扩展修改后检查资源加载；安装声明、依赖或上游来源变化时，依次运行现有 `scripts/setup.mjs` 的 `prepare`、`link`、`check`。Pi Web 的构建与安装按其[包说明](../packages/pi-web/README.md)执行，不为无关插件更新重建 Pi Web。
- 配置验收验证实际资源与工具接线，不调用商业模型、不生成图片。新会话使用新资源；已有会话通过 `/reload` 更新，不强制重启其他会话。

## 发布与多端同步

获得相应授权后，核对 diff 和暂存区，只提交本次内容，再执行 push；对端操作另按授权执行。同步使用目标仓库的快进拉取，并按实际变化准备资源、验证加载。遇到离线、脏工作区、分叉或来源不符，保留现场并报告，不自动重试、stash、reset 或强拉。

分别报告本机修改、commit／push、对端 revision 和资源验证状态；资源就绪不等于运行中的会话已换配置。
